## 一、本版做了什么

在 v0.3.0-local.3（P0–P3：专辑切换零卡顿、AMLL 级歌词动效、歌词参数模块）之上，完成**第三轮 P4——数据源扩充**：给「线上补充专辑详情与背景」新增三个来源，并用真实全库重新测了覆盖率。

### 1. 网易云音乐（核心新增，爬虫爬取专辑背景知识）

- 流程：`/api/search/get/web`（搜索定专辑 id）→ `/api/v1/album/{id}`（取详情）
- 抓取字段：**长中文简介 `description`**、发行日期、唱片公司、收录曲目数
- 简介是繁体，已自动**繁转简**并压缩多余空白
- 与 QQ 音乐共用同一套"双重复核"防错答：搜索结果名称对上 → 详情名称再对一次，任何一步不符就拒绝

> ⚠️ 网易云的 `/api/album/{id}`（非 v1）会返回风控 `code:-462`，只有 `/api/v1/album/{id}` 免登录可答，代码里固定走 v1。

### 2. Discogs（best-effort 末位）

- 提供年份 / 流派 / 载体（CD / Vinyl / Album 等）facts，无长简介
- 只在主来源全部"没找到"时才发起；失败只空自己那一行，不影响整体

### 3. Wikidata（best-effort 末位）

- 提供发行日期（P577）一个 fact
- 本机实测**极不稳定**（时 4–5s 成功、时 8–10s 超时），因此给了独立的 3 秒预算 + 熔断，绝不拖慢正常专辑的打开

### 4. 可达性自检

- 新增 `check-music-online-sources.mjs`：逐主机报告「状态 / 耗时 / 是否 JSON」，纳入 `check:music`。以后哪个源挂了，跑一次自检就能发现，不用等你点开详情页才发现。

## 四、请你在真机确认

1. 点开一张「线上补充详情与背景」：出处列表是否出现「网易云音乐」（QQ 没覆盖的专辑会更多）

## 五、已知边界

- **Wikidata 本机不稳定**：已按 best-effort 处理（3s 预算 + 熔断 30 分钟），但若你觉得它价值太低、只拖慢首次查询，可以随时让我把它从末位来源里摘掉。
- **Discogs 搜索不带歌手名**：Discogs 对中文歌手名匹配返回 0 行，所以只按专辑名搜、再从结果里按 "Artist - Title" 拆行匹配歌手。这是实测结论，不是缺陷。
