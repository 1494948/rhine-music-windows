## 一、这一版做了什么

### 1. 修复专辑浏览的跨列卡顿

**根因**：跨列一步会让整列槽位重新映射，逼出一次完整图集上传；图集按"总槽位数"分配大小，79 张曲库时为 4096×6912 RGBA ≈ 108 MB，而每个专辑实际只占一格 —— 一次绘制就要重传 108 MB。叠加封面在主线程缩放。

**做法**：图集改为按"同帧可达专辑数"分配（108 MB → 20 MB）；封面缩放改走 `fetch` + `createImageBitmap` 移到主线程外；已缓存的缩略图一次绘成；图集支持扩容。

### 2. 专辑档案区块（发行背景 / 专辑意义）

详情页参数表下方新增 `ARCHIVE ／ 档案`。内容按**四级来源**解析，并且**永远标注用的是哪一级**，绝不把推断写成有出处的事实：

| 级别 | 来源 | 允许写外部事实？ |
|---|---|---|
| 1 | `app/content/album-archives.json`（人工补录） | 是，且必须带 `sources` |
| 2 | 线上补录（实时抓取，逐条附出处与许可） | 是，且必须带出处 |
| 3 | 本机已核对的专辑介绍 | 是（先前已附出处） |
| 4 | 由本地数据推导（档案编号、时长分布、无损占比、采样率范围…） | 否，纯本地算术 |

### 3. 小白条：详情 ⇄ 歌词切换控件

三层光学结构（外层呼吸光晕 / 中层紧致光晕 / 上层受光胶囊，胶囊内有一道缓慢划过的光泽），三层用**不同周期与负延时**各自漂移，所以看起来是"光在浮动"而不是"一个形状在上下滑"。

- **单击锁定**：待机浮动**原地冻结**（`animation-play-state: paused`，而不是 `animation: none` —— 后者会把图层弹回基准位，点击瞬间会跳），白条变实心，再点解锁。
- **拖动**：胶囊被"捏住"压缩，松手用更慢的曲线弹回，两个方向时序不对称。
- **惯性**：拖动时采样速度，松手把速度**交给弹簧**。快速一甩按甩动方向直接翻到底，不是"松手就归位"。
- **键盘可达**：`Tab` 后可 `Enter`/`空格`/`↑`/`↓`/`Home`/`End` 操作，并有可见焦点环（上一版完全没有焦点样式）。
- 全程只写 `transform` / `opacity` / `scale`，不触发重排；尊重系统"减少动态效果"。
- 落点仍由 CSS 变量 `--switch-top` / `--switch-bottom` 控制，调位置不用改代码。

### 4. 歌词管线与动效

- 歌词**不写入曲库索引**，走 `GET /api/lyrics/:trackId` 按需读取 + 文件指纹缓存，索引体积不受影响。
- 来源优先级：同名 `.lrc`（`.lrc/.LRC/.zh.lrc/.zh-CN.lrc/.zh_CN.lrc`）→ 内嵌 SYLT（逐字）→ 内嵌 USLT。`.lrc` 按 UTF-8 → GB18030 → GBK → Big5 依次尝试。
- 逐字同步走 `clip-path` 扫过，四级距离分层（far/mid/near/0）控制透明度与缩放。
- **只在用户第一次开始拖动小白条时才解析并渲染歌词**，打开专辑本身不变慢。

### 5. 线上补充专辑详情与背景（本版补齐的功能）

- 服务端新增 `GET /api/album-online/:id`，来源为 **MusicBrainz**（专辑类型 / 首次发行 / 匹配度）、**Apple Music 商店**（上架日期 / 流派 / 曲目数 / 版权）、**维基百科**（简介正文）。免密钥，音乐文件不上传。
- **不编内容**：正文只引用来源原文，摘要只用来源真正返回的字段拼装，每条来源附许可与校对时间。
- **不互相拖累**：三个来源并发、各自限速；整体 12 秒预算，超时的来源记为"已放弃"而不是让页面无限等；单个来源连接失败后会**熔断 30 分钟并落盘**（本机维基百科被 DNS 污染，79 张专辑只付出 1 次超时，其余 77 张直接跳过）。
- **限流重试**：MusicBrainz 的 503/429 按官方要求退避重试一次（实测把《七里香》从失败变命中）。
- 结果缓存在 `music-data-v3\album-online\`，TTL 30 天，按专辑身份指纹校验。
- 界面上"未找到"和"不可达"**分开显示**，并给出可执行的下一步（"补全名称、歌手与年份会显著提高命中率"）。
- 「资料库设置」里的"扫描后自动补充"开关只管自动补录；**手动点击不受它限制**，所以默认配置下功能不会静默失效。

### 6. 分发形态

- 新增可复现的打包脚本 `scripts/package-windows.mjs`。
- `app/node_modules` 从 110.5 MB 裁到 **6.74 MB**（按 `music-server.mjs` 的真实导入闭包计算，不是猜的）。
- 排除 `music-data-v3/webview2`（115 MB 的 WebView2 浏览器配置，属运行状态，首次启动自动重建）。
- 补上一个基座文档提到但实际缺失的 `启动音乐播放器.bat` 备用启动方式。

### `npm run check:music`（14 个脚本）

**12 通过 / 2 失败**。两个失败都是**基线既有缺陷**，与本次改动无关，本次未改动：

1. `check-music-player.mjs` — `src/music-player.ts:6` 以无扩展名写法导入 `"./native-playback"`，Node 的 `--experimental-strip-types` 无法解析（全仓库共 100 处这种上游写法）。
2. `check-music-model.mjs` — 二次修改者调了白天主题玻璃粗糙度却没同步校验阈值（day 期望 0.42–0.50）。

**本次新增 2 个检查脚本**，均通过：

| 脚本 | 覆盖 |
|---|---|
| `check-music-online.mjs` | 命中装配 / 近失不采用 / 全部不可达 / 12 秒预算 / 限流重试 / 熔断落盘 / 缓存命中 / TTL 过期 / 身份指纹 / 来源与许可齐全 / 只访问白名单主机 |

另外扩充了 `check-music-lyrics.mjs` 的样式与接线契约断言：新增的小白条三层类名、`switch-breathe`/`switch-glint`、`animation-play-state: paused`、`:focus-visible`，以及 `online-album`/`online-library` 两个动作与 `data-status="online"` 的选择器。
