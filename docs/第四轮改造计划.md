> 规划日期 2026-10-09。本文件是"换模型写代码"的交接文档，实现前先读本文 + `PROJECT.md`。

## 0. 一句话结论

上游 `RonaldDeng/Rhine-Music-Demo` 的 `v0.3.0 → v0.4.1` 是 **193 文件 / +2 万行**的大版本跳：
作者把 v0.3.1（光照实验）+ v0.4.0（FFmpeg/CoreAudio、总览模式、真实专辑列、专辑盒重做）+
v0.4.1（无缝播放、开场、滚轮导航、歌名裁切、QQ 制作名单）**全部 squash 进单个提交 `c7da0b5`**。
目标：把这批新特性**一次性全量**移植进本地 Windows 版 `rhine-music-local-mod`，并另起一个 Android 版。

## 1. 关键架构事实（实现前必读，别踩）

1. **目录映射**：上游根目录 `src/`、`scripts/`、`index.html`、`package.json` ↔ 本地 `app/src/`、
   `app/scripts/`、`app/index.html`、`app/package.json`。移植时逐个加 `app/` 前缀。
2. **本地基线 = 上游 v0.3.0 + 3 个额外文件**：`src/native-playback.ts`、`src/dof-pass.ts`、
   `src/sharpen-pass.ts`（第三方 libmpv 壳，Windows 专属）。与上游 v0.4.1 曾有的
   `windows/RhineMusic.cs`（C# 壳）是**两套不同实现**，不要混淆。
3. **v0.4.1 是 macOS 专属**：音频 = `native/RhineAudio.swift`（FFmpeg 解码 + CoreAudio 输出），
   Windows 无原生音频层。→ 音频后端**保持 libmpv 不变**（用户已拍板）。
4. **npm 依赖 v0.4.1 与 v0.3.0 完全一致**（three / music-metadata / opencc-js / rolling-number），
   **没有任何新依赖**。移植是纯代码合并，不用装新包。
5. **"在线书架（Internet Archive + Subsonic）不是 v0.4.1 的正式特性**：它是 MT-gar PR #1 加的
   `scripts/online-sources.mjs`，但作者在 `c7da0b5` 里把它删了（`git show v0.4.1:scripts/online-sources.mjs`
   报 not exist）。所以**无需移植，也无需与本地线上来源（QQ/网易云/百科/MusicBrainz/Discogs/Wikidata）冲突处理**。
6. **上游 clone 已就位**：`playground/rhine-v041-port/upstream`（`--filter=blob:none` 浅克隆，含全部 tag）。
   直接 `git -C "C:/AI Document/playground/rhine-v041-port/upstream" diff v0.3.0 v0.4.1` 可取 per-file 差异。

## 4. 任务 2 · Android 版（按 v0.4.1）

### 4.1 架构

- **前端**：复用 Vite 构建的 three.js 页面，做手机尺寸适配（横屏为主，参考上游竖屏/详情规则与
  `review:mobile` / `serve-mobile-review.mjs` 脚本）。
- **壳**：原生 `MainActivity` + `WebView`，静态资源内嵌 assets（不依赖本地 Node 服务）。
- **音频**：`ExoPlayer` / `MediaPlayer`，通过 `JavascriptInterface` 桥接给前端调用。
- **曲库**：`MediaStore` 查询本地音频 + `MediaMetadataRetriever` 读标签/封面，替代桌面版的
  `music-server.mjs` + `music-metadata` 扫描。

### 4.2 本机工具链（已就位，无需重搭）

- `playground/android-toolchain/` 已有：`android-sdk`、`cmdline-tools`、`gradle-8.7`、`gradle-home`、
  `zulu17.50.19`（JDK 17）。**但 `JAVA_HOME` / `ANDROID_HOME` 未导出**，构建脚本里需先 set。
- 完整流程见本地技能 `android-apk-build-windows`（本机裸机搭工具链出 APK）。

### 4.3 阶段

1. **阶段 1**：前端移动端适配（视口/字号/触控）→ `vite build` 出移动端产物。
2. **阶段 2**：`WebView` 壳 + assets 内嵌 + 本地静态服务兜底。
3. **阶段 3**：`MediaStore` 曲库 + `MediaMetadataRetriever` 标签/封面 + `ExoPlayer` 播放 + JS 桥。
4. **阶段 4**：出 APK + 真机验证（画面/性能/尺寸适配）。

## 5. 遗留与风险（实现时注意）

- **无 GPU 环境**：动效/手感/图集脏矩形上传方向需用户真机目视确认（沿用前三轮做法）。
- **三方合并风险高**：建议按 A 档 → B 档 → 打包分步提交，每步可回滚，不要一次合完。
- **Android WebView 里 three.js 的性能**：手机 GPU 跑 4096×1280 图集 + 后处理可能吃紧，
  必要时降图集分辨率 / 关后处理，需真机实测"性能过得去"。
- **移植前先打 tag** 保护当前 `v0.3.0-local.4`（`v0.3.0-local.4` 基线），失败可整体回滚。
