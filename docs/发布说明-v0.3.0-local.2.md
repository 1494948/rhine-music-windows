## 一、这一版做了什么

这一版处理四件上一版留下的事：**换专辑时"依旧存在"的卡顿**、**歌词细线与动效**、**歌词参数不可调**、**线上来源在国内不可用**。

### 1. 换专辑卡顿：两处实测主因

上一轮把图集改成"按专辑键控"后，滚动与换列不再重绘；剩下的是**换风格/换列时一整排新专辑进入图集**这一次。

- **图集整面重传**：`CanvasTexture.needsUpdate = true` 会把整张图集（4096×1280 RGBA ≈ **21 MB**）重新上传。一次导航最多约 48 张新专辑 → 最多约 **1 GB 纹理流量**。现在只把刚画好的 256×256 瓦片（**262 kB**）用 `texSubImage2D` 补进那一块矩形，约 **80×**；无法补时自动回退整面上传。
- **详情栏整栏重建**：`renderDetail()` 原本每次换专辑都 `innerHTML` 重写整根阅读栏，于是**每次都要重建带 `backdrop-filter: blur(18px)` 的标签栏**、重解析档案面板与 8 行参数表，还多一次指示器的强制同步布局。现在骨架建一次、只写变化的区域，选中态未变时连指示器读取都跳过。

**已知风险（需要你目视确认一次）**：子矩形纵向落点依赖 three 的翻转上传约定，本机无 GPU 无法自动验证。它已提取为具名纯函数，并与着色器 UV 的独立推导逐行比对（4 种行数 × 2 种瓦片尺寸）。若封面出现错位或镜像，把 `CoverAtlas.uploadTile()` 的返回值改成恒 `false` 即整体回到整面上传——**正确性不变，只损失性能**。

### 2. 歌词：细线移除 + 按 Apple Music 动效模型重做

- 删掉了正在演唱那一行下方的**细线**（原 `.lyric-line[data-d="0"]::after`，1px `var(--line)`，由 `--line-p` 缩放），以及它的无同步歌词覆盖规则、每帧的 `--line-p` 写入和随之失效的 `lineEndTime` 引入。
- 逐字层从 `clip-path` **硬切**改成**柔边遮罩**（`mask-image`），柔边宽度以字号为单位（即 Apple Music 的 `wordFadeWidth`；0.5 接近 iPad 版，1 接近安卓版）。
- 新增：正在唱那一行**未唱部分降亮**（"扫过"的对比来源）、**字号纵深**（非高亮行按比例缩小，而非缩放 transform，字形保持锐利）、`lyric-float` 待机浮动（起止都在 0 位，交接给下一行不跳变）、高亮行辉光。
- 有意**不做**逐行 `scale` 动画：那会让 50–60 个已定位、带 `blur()` 的行每帧重新光栅化。字号纵深拿到了同样的视觉层次，代价低得多。

### 3. 「歌词」参数设置模块（新增）

设置面板最下面新增「歌词」一节，**11 项参数 + 实时预览**，改动即时生效并自动保存：

歌词字号 · 行距 · 非高亮行缩放 · 逐字渐变宽度 · 未唱部分浓度 · 高亮行辉光 · 浮动幅度 · 浮动周期 · 虚化强度 · 整体明暗 · **歌词偏移（±800 ms，用来对齐个别歌词文件的时间轴）**；另有高亮颜色 / 歌词颜色两个取色块，可一键「跟随主题」，以及「恢复默认参数 ↺」。

预览用的是**与播放页同一套 token 和同一套 `data-d` 分层**，不是另画一份，所以不会出现"预览好看、实际不一样"。参数存在 `rhine-lyric-preferences`，与音频、质量等偏好互不影响。

### 4. 线上来源：换成国内可正常访问的集合

| 来源 | 主机 | 覆盖率（真实 79 张） | 说明 |
|---|---|---|---|
| **QQ 音乐** | `c.y.qq.com` | **38 / 79（48.1%）** | 唯一提供**长中文简介**（叶惠美 2568 字）；免密钥 |
| **百度百科** | `baike.baidu.com` | **33 / 79（41.8%）** | 只用官方开放 API |
| MusicBrainz | `musicbrainz.org` | 39 / 79 | 类型 / 首次发行 / 匹配度，CC0 |
| Apple Music 商店 | `itunes.apple.com` | 1 / 39 | **降级为二阶段**：仅当国内三源全部"没找到"才发起 |
| ~~维基百科 / Wikidata~~ | — | 0 | **整体删除**（本机 DNS 污染，79 张贡献 0） |

三源合计 **57%**。两条**错答防护**是这一版的重点（两个来源对歧义名称都会自信地返回错东西）：

- **QQ 音乐**：建议接口按热度排序，返回的 mid 可能是别的专辑 → 取详情后**再用详情自己的专辑名复核一次**。
- **百度百科**：一个关键词只解析到一个词条（「叶惠美」查到的是一位母亲，「丝路」查到的是丝绸之路）→ 摘要须同时含 `《专辑名》`、含 `发行/收录/推出`、含歌手名之一，否则拒绝并回显前 36 字。

另外新增**标题清洗**（本地标题带 `<…>`、`(Live)`、` - Single` 包装时先洗净再查，实测多命中 2 张）与**语句槽位去重**（QQ 的发行日期与 MusicBrainz 的首次发行日期说的是同一件事，原先会把同一个日期说两遍）。

## 三、怎么打开

1. 解压整个文件夹（**不要**只拖 `RhineMusic.exe` 出来，它需要同目录的 `libmpv-2.dll`、`runtime\`、`app\`）。
2. 双击 `RhineMusic.exe`。
3. 首次启动会创建 WebView2 配置目录（约 14 MB），稍慢属正常。

## 四、这一版仍需你确认的事

1. **图集子矩形落点的上下方向**（见 §一.1 的"已知风险"）—— 看封面是否显示成正确的专辑、方向是否正常。
2. 换风格/换列的**手感**是否已经"完全解决"，还是仍能感知到停顿。
3. 「设置 → 歌词」的各项参数在你的屏幕上是否顺手（尤其"逐字渐变宽度"和"歌词偏移"）。
4. 小白条与歌词动效的观感。

以上四项都需要真实 GPU 与你的屏，本机（无浏览器环境）无法自动校验。
